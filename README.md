# Inter-Lab Spectroscopy Bridge: Cheng's Computer to Zoe's Computer Integration Contract

This document defines the communication protocol, file formats, and execution modes between Cheng's Computer (Mac / New A2) and Zoe's Computer (Windows 11 Wavemeter & PID Controller).

---

## 1. System Overview & Transport Layer
* **Protocol:** HTTP REST API running locally on Zoe's Computer on port `5000`.
* **Endpoints:**
  * `POST /upload_params`: Cheng's Computer uploads parameter configuration files to Zoe's Computer `Inbox`.
  * `GET /list_outbox`: Cheng's Computer requests a JSON list of available telemetry npy files in Zoe's Computer `Outbox`.
  * `GET /download/<filename>`: Cheng's Computer downloads a specific telemetry npy file.

---

## 2. Operating Modes (`MODE`)

Zoe's Computer script supports two distinct operational states defined within the parameter files:

### A. Test Mode (`MODE = TEST`)
* **Purpose:** Used for tuning PID coefficients, checking laser locking stability, and evaluating free-running oscillations *before* the experimental hardware trigger loop is active.
* **Behavior:** Zoe's Computer reads the latest available parameter file in the `Inbox` (or a designated `test_params.txt`) and continuously runs the PID loop against the wavemeter. It streams telemetry npy files periodically without waiting for a hardware trigger. The output file should overwrite, and include all of the test_params as part of the data.

### B. Run Mode (`MODE = RUN`)
* **Purpose:** The actual automated binary search experiment coupled with the main experimental loop.
* **Behavior:** Zoee's Computer arms itself, waiting for the physical TTL hardware trigger from the experiment. Upon each rising edge, it consumes the **next sequential parameter file** in the `Inbox`, executes the frequency sweep/PID update during the trigger window, logs data, moves the parameter file to an `Archive/` subfolder, and drops the resulting telemtry npy into the `Outbox`.

---

## 3. Parameter File Format (Cheng's Computer -> Zoe's Computer Inbox)
* **File Naming Convention:** `params_[YYYYMMDD_HHMMSS_ms].txt`
* **Lifecycle:** Created by Cheng's Computer -> Uploaded to Zoe's Computer `Inbox` -> Read and moved to `Archive/` by Zoe's Computer upon execution.
* **Payload Structure:**
```text
MODE = RUN
TARGET_ID = shot_042
START_FREQ_THZ = 384.000000
TARGET_STOP_FREQ_THZ = 384.120000
SWEEP_RATE_MHZ_PER_MS = 2.0
KP = 1.2
KI = 0.15
KD = 0.01
DIGITAL_CHANNEL = 0
RAMP_DELAY_MS = 20 
```

---

## 4. Telemetry File Format (Zoe's Computer Outbox -> Cheng's Computer)
* **File Naming Convention:** `telemetry_[YYYYMMDD_HHMMSS_ms].npy`
* **Lifecycle:** Generated by Zoe's Computer immediately after a trigger window ends -> Placed in `Outbox` -> Downloaded and processed by Cheng's Computer.
* **npy Column Specification:**
```npy
Timestamp_ms,Trigger_Status,Wavemeter_Freq_THz,PID_Error,DAC_Output_V
0,HIGH,384.000000,+0.000100,2.100
1,HIGH,384.002000,+0.000050,2.102
...
60,LOW,384.120000,-0.000010,2.250
```
